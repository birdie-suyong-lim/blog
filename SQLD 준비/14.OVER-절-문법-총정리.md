## 1. OVER 절의 전체 구조부터

윈도우 함수는 전부 이 한 줄 구조로 되어 있다. 괄호 안의 세 파트가 각각 무엇을 하는지만 잡으면 문법의 대부분이 끝난다.

```sql
함수명(인자) OVER (
  PARTITION BY 컬럼    -- 1) 그룹 나누기 (생략 가능)
  ORDER BY 컬럼        -- 2) 그룹 안에서 줄 세우기 (생략 가능)
  ROWS BETWEEN ...     -- 3) 계산 범위(프레임) 지정 (생략 가능)
)
```

| 파트 | 역할 | 생략하면 |
|---|---|---|
| PARTITION BY | 행들을 그룹(파티션)으로 분할 | 전체 결과가 하나의 파티션 |
| ORDER BY | 파티션 내부 정렬 기준 | 순위 함수는 사용 불가, 집계 함수는 파티션 전체 대상 |
| ROWS / RANGE | 파티션 안에서 실제 계산할 행 범위 | 기본 프레임 적용 (아래 6번) |

GROUP BY와 달리 행이 줄어들지 않는다 — 모든 행이 그대로 남고, 각 행에 계산 결과가 컬럼으로 붙는다. 이 차이는 [7번 글](7.윈도우함수와-GROUP-BY의-차이.md)에서 정리했으니, 여기서는 괄호 안 문법 자체를 판다.

## 2. 순위 함수 3형제: RANK, DENSE_RANK, ROW_NUMBER

시험 최다 출제. 셋의 차이는 "동점(같은 값)을 어떻게 처리하는가" 하나뿐이다.

```sql
SELECT 사원명, 급여,
       RANK()       OVER (ORDER BY 급여 DESC) AS rk,
       DENSE_RANK() OVER (ORDER BY 급여 DESC) AS drk,
       ROW_NUMBER() OVER (ORDER BY 급여 DESC) AS rn
FROM 사원;
```

| 급여 | RANK | DENSE_RANK | ROW_NUMBER |
|---|---|---|---|
| 5000 | 1 | 1 | 1 |
| 4000 | 2 | 2 | 2 |
| 4000 | 2 | 2 | 3 |
| 3000 | 4 | 3 | 4 |

- RANK: 동점은 같은 순위, 다음 순위는 건너뜀 (1, 2, 2, 4). 올림픽 메달 방식.
- DENSE_RANK: 동점은 같은 순위, 다음 순위는 촘촘하게 (1, 2, 2, 3). "몇 번째 급여 수준인가".
- ROW_NUMBER: 동점이어도 무조건 고유 번호 (1, 2, 3, 4). 동점끼리의 순서는 보장되지 않는다.

기억법: RANK는 건너뛰고(gap 있음), DENSE는 빽빽하고(gap 없음), ROW_NUMBER는 그냥 행 번호다. 시험에서는 결과 표를 주고 "이 출력이 나온 함수는?"을 묻거나, 세 함수의 출력 숫자를 서로 바꿔 놓는 패턴이 대부분이다.

순위 함수 3형제는 모두 OVER 안에 ORDER BY가 필수다. 없으면 줄 세울 기준이 없으므로 에러다.

## 3. PARTITION BY — 그룹별로 다시 1등부터

PARTITION BY가 붙으면 순위가 파티션마다 새로 시작된다.

```sql
SELECT 부서, 사원명, 급여,
       RANK() OVER (PARTITION BY 부서 ORDER BY 급여 DESC) AS 부서내순위
FROM 사원;
```

| 부서 | 사원명 | 급여 | 부서내순위 |
|---|---|---|---|
| 개발 | 김개발 | 5000 | 1 |
| 개발 | 이코드 | 4000 | 2 |
| 영업 | 박영업 | 4500 | 1 |
| 영업 | 최세일 | 3000 | 2 |

"부서별 급여 상위 2명"처럼 그룹별 Top-N을 뽑을 때 이 형태를 인라인 뷰에 넣고 바깥에서 `WHERE 부서내순위 <= 2`로 거른다. 윈도우 함수는 WHERE 절에 직접 쓸 수 없다는 것도 함께 기억 — SELECT의 결과에 붙는 값이라 WHERE 시점엔 존재하지 않기 때문이다.

## 4. 행 참조 함수: LAG, LEAD

현재 행에서 앞뒤 행의 값을 가져온다. 전월 대비 증감 같은 문제에 나온다.

```sql
SELECT 월, 매출,
       LAG(매출)     OVER (ORDER BY 월) AS 전월매출,   -- 이전 행
       LEAD(매출)    OVER (ORDER BY 월) AS 익월매출,   -- 다음 행
       LAG(매출, 2, 0) OVER (ORDER BY 월) AS 두달전    -- 2행 전, 없으면 0
FROM 월매출;
```

- LAG(컬럼, n, 기본값): n행 이전 값. n 생략 시 1, 기본값 생략 시 NULL.
- LEAD(컬럼, n, 기본값): n행 이후 값. 인자 규칙 동일.
- 첫 행의 LAG, 마지막 행의 LEAD는 참조할 행이 없어 NULL(또는 지정한 기본값)이 된다 — 이 NULL 처리를 묻는 보기가 자주 나온다.

## 5. 그 외 자주 나오는 함수들

| 함수 | 역할 | 비고 |
|---|---|---|
| SUM/AVG/MAX/MIN/COUNT ... OVER | 집계값을 행마다 붙임 | ORDER BY를 넣으면 누적 집계가 됨 |
| FIRST_VALUE(컬럼) | 파티션(프레임) 내 첫 값 | 프레임 기본값 영향 없음 |
| LAST_VALUE(컬럼) | 파티션(프레임) 내 마지막 값 | 기본 프레임 때문에 "현재 행까지"의 마지막이 됨 — 함정 단골 |
| NTILE(n) | 행을 n등분해 몇 번째 구간인지 반환 | 4분위 나누기 등 |
| RATIO_TO_REPORT(컬럼) | 파티션 합계 대비 비율 | 합계 대비 점유율 |

누적합이 만들어지는 이유는 다음 문법 때문이다:

```sql
SUM(매출) OVER (ORDER BY 월)                      -- 누적합 (기본 프레임)
SUM(매출) OVER (PARTITION BY 지점 ORDER BY 월)     -- 지점별 누적합
SUM(매출) OVER ()                                 -- 전체 합계를 모든 행에
```

같은 SUM인데 ORDER BY 유무로 "누적 vs 전체"가 갈린다. 이게 다음 섹션의 기본 프레임 규칙이다.

## 6. 프레임(ROWS BETWEEN) — 기본값이 함정이다

프레임은 "파티션 안에서 실제로 계산에 넣을 행 범위"다.

```sql
SUM(매출) OVER (ORDER BY 월
  ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)  -- 처음~현재 행 = 누적
SUM(매출) OVER (ORDER BY 월
  ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)          -- 최근 3개월 이동합
SUM(매출) OVER (ORDER BY 월
  ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)  -- 파티션 전체
```

키워드는 다섯 개뿐이다: `UNBOUNDED PRECEDING`(파티션 처음), `n PRECEDING`(n행 앞), `CURRENT ROW`(현재 행), `n FOLLOWING`(n행 뒤), `UNBOUNDED FOLLOWING`(파티션 끝).

핵심 함정 — ORDER BY만 쓰고 프레임을 생략하면 기본 프레임은 `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`, 즉 "처음부터 현재 행까지"다. 그래서:

- `SUM ... OVER (ORDER BY 월)`이 전체합이 아니라 누적합이 된다.
- `LAST_VALUE ... OVER (ORDER BY 월)`이 파티션의 마지막 값이 아니라 그냥 현재 행 값이 된다. 진짜 마지막 값을 원하면 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`을 명시해야 한다.

ROWS와 RANGE의 차이도 한 줄로: ROWS는 물리적 행 개수 기준, RANGE는 ORDER BY 값 기준(동일 값이면 한 덩어리로 취급). 동점 행이 있을 때 누적합 결과가 달라진다 — RANGE는 동점 행들이 같은 누적값을 갖는다.

## 7. 시험 포인트 요약

- OVER 괄호 구조: PARTITION BY(그룹) → ORDER BY(정렬) → ROWS/RANGE(범위). 셋 다 생략 가능하지만 순위 함수는 ORDER BY 필수.
- RANK 1,2,2,4 / DENSE_RANK 1,2,2,3 / ROW_NUMBER 1,2,3,4 — 동점 처리만 다르다.
- 윈도우 함수는 행 수를 줄이지 않고, WHERE 절에 직접 못 쓴다(인라인 뷰로 감싸서 필터).
- ORDER BY가 있으면 기본 프레임은 "처음~현재 행" → SUM은 누적합, LAST_VALUE는 현재 행 값.
- LAG/LEAD의 경계 행은 NULL(기본값 지정 가능).
